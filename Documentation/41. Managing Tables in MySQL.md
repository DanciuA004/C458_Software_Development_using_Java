# Relational Databases and MySQL

## Managing Tables in MySQL

### 1. Create a Table

Before we get to the point of trying to code a table in SQL, we should always take the time to design the entire database on paper (real or digital), using an ERD or similar tool. Going through the design steps required to normalize and plan a database will make the SQL part of building the database much more straightforward, because we will enter the RDBMS knowing exactly what tables we need, what fields will be in each table, what data types each field should have, and which fields should be defined as key fields.

If you create tables without having all of this information up front and then start entering data into those tables, it will be very difficult to fix problems without having to delete and rebuild the database from scratch.

The basic syntax to create a table is:

        CREATE TABLE tableName (
            field1 datatype,
            field2 datatype,
            field3 datatype
        );

When we define a table, we must include both a name and a data type for each column in the table at minimum. We can also define additional parameters on individual fields, including indexes, how values are assigned to primary keys, whether the field is nullable, and any constraints that we want to apply to specific fields.

Let's create a simple table with the following description from an ERD:

Table name: book

Field list:

* bookId INT PK
* bookTitle VARCHAR(100) required
* numPages SMALLINT
* origPubDate YEAR

We selected the data types for the following reasons:

* bookId:
  * The primary key value will be a randomly-assigned integer. We choose INT to allow for a large collection of books.
  * By default, any primary key field is also required, so we don't need to specify that as an extra step.
* bookTitle:
  * Each book has a different length title, so we use VARCHAR instead of CHAR.
  * While it's not impossible that a book's title will have more than 100 characters, this is a reasonable maximum for expected book titles.
  * We want to be sure that we know the title of each book in the database, so we make this field required.
* numPages:
  * We choose SMALLINT here, which has a maximum unsigned value of 65,535. No book in our collection should have more than that many pages, and SMALLINT requires less storage space than INT.
  * This field is not required. We may have books in our collection for which we do not have this value, so we want to be able to leave it empty.
* origPubDate:
  * We will use this field to store the year the book was originally published, which may be different from the publication date of actual books in our collection.
  * We only need the YEAR value rather than a specific time.

Note that we have not included author information or format data in this table. In the design phase of creating this database, we determined that there is a many-to-many relationship between book and author, which is reflected in separate bookAuthor and Author tables. Similarly, the format and ISBN values for a book are specific to the physical book, so this data would also appear in a different table.

Because we have defined the table in an ERD, it is very simple to write a SQL statement to create this table in MySQL. For now, we will include only the column names and data types:

    USE books;
    
    CREATE TABLE book (
        bookId INT,
        bookTitle VARCHAR(100),
        numPages SMALLINT,
        origPubDate YEAR
    );

### 2. List Tables

You can verify that the table was created using a SHOW TABLES statement:

        SHOW TABLES;

This will list all tables available in the current database. At this point, if you have created the book table in the books database, the results would look like:

        Tables_in_books
        ----------------
        book

### 3. View a Table

There are many different options in MySQL for seeing how a table is structured, but the most straightforward is the DESCRIBE keyword with the name of the table.

        DESCRIBE book;

In this example, the results are:

        Field       Type            Null    Key     Default     Extra
        bookId      int             YES             NULL 	 
        bookTitle   varchar(100)    YES             NULL 	 
        numPages    smallint        YES             NULL 	 
        origPubDate year            YES             NULL

Note that at this point, all of the fields in the table are nullable, which is the default setting. We must specify which fields are not nullable.

### 4. Change a Table

You may realize that you missed something when you first created a table. For example, you may realize later that you need another field, that one of the fields you started with is no longer needed because of how the database is used, or that some other setting is missing, such as defining a field to be required. For this reason, SQL includes the ALTER TABLE statement.

In looking at the table we just created, we realize that numPages isn't really needed there. The actual number of pages will depend on the format, not on the abstract version of the book that this table represents, so we can use ALTER TABLE to remove it.

        ALTER TABLE book
            DROP numPages;

In this example, the ALTER TABLE statement drops (or removes) the field named numPages. If we describe the table again, the field is missing.

        Field       Type            Null    Key     Default     Extra
        bookId      int             YES             NULL 	 
        bookTitle   varchar(100)    YES             NULL 	 
        origPubDate year            YES             NULL

We can use the ALTER TABLE command to change almost any field in the table. in this case, we know that bookId should be the primary key. Ideally, we should have defined this when we first created the table, but since we didn't, we can change it now.

Keys (both primary and foreign) create constraints on how the fields and table behave and they need names just like the fields do. As a matter of convention, primary key names typically start with PK and include the name of the table for which it is the primary key. In this case, we will name the key PK_book. We also have to identify what kind of constraint it is and which field(s) it applies to.

We can set a primary key on the book table using the following statement:

        ALTER TABLE book
            ADD CONSTRAINT PK_book PRIMARY KEY (bookId);

Describing the table now includes the primary key on bookId:

        Field       Type            Null    Key     Default     Extra
        bookId      int             NO      PRI     NULL 	 
        bookTitle   varchar(100)    YES             NULL 	 
        origPubDate year            YES             NULL

Note, too, that the Null status for bookId changed from YES to NO in the same step. By definition, primary key fields cannot be null, so this setting is applied automatically when a field is designed as a primary key.

In our original description of the table from the ERD, we also want bookTitle to be required, and we can use ALTER TABLE to adjust that as well.

        ALTER TABLE book
            MODIFY bookTitle VARCHAR(100) NOT NULL;

Note that when we modify a field we must modify all aspects of that field, even those we are not changing.

Describing the table gives us:

        Field       Type            Null    Key     Default     Extra
        bookId      int             NO      PRI     NULL 	 
        bookTitle   varchar(100)    NO              NULL 	 
        origPubDate year            YES             NULL

> For more details on other options for changing existing tables, see TechOnTheNet's page, MySQL: ALTER TABLE Statement.

### 5. ALTER Tables with Existing Data

If a table contains data, it may not be possible to MODIFY a column. If you declare a column NOT NULL and your data contains nulls, the MODIFY will fail. Likewise, if you MODIFY a column to use a more restrictive data type, say, VARCHAR(10) versus VARCHAR(50), and your column contains values longer than 10 characters, your MODIFY will fail.

To force the modification, update the data to conform to restrictions and then MODIFY.

### 6. Delete a Table

If you have created a table that you no longer need, you can delete it using a DROP TABLE command.

        DROP TABLE book;

And you can use the SHOW command to verify that the table has been removed from the database.

        SHOW TABLES;

In this case, we are deleting the only table in the books database, so the result is an empty set.

> This is Dangerous!  
> When you delete a table, you delete everything in that table, including any data stored in the table.
