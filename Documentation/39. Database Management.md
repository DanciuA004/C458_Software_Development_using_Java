# Relational Databases and MySQL

## Database Management

### 1. Create a New Database

Let's create a new database that will store the data related to a bookstore's inventory.

When we create a database in an RDBMS, we are essentially creating a storage area that will hold all of the information about that database, including its objects (including tables, views, and stored procedures) and the data itself. The RDBMS will impose some limits on the contents of a database, including the fact that each object within a database must have a unique name. This means that we cannot have two tables with the same name, nor can we have a table and a view with the same name.

This does, however, allow us to have tables with the same name in separate databases on the same RDBMS, just as we can have fields with the same name in separate tables in the same database.

SQL naming requirements are reasonably relaxed, and the only real requirement is that an identifier must start with a letter. Otherwise, we recommend:

* Include only letters, numbers or the underscore character (_) in any identifier
* Avoid spaces, dots, or other unusual characters
* Follow established naming conventions for identifiers that include multiple words.

For the examples here, we will generally use camelCasing for object names.

Creating a database in SQL is very straightforward. After connecting to the RDBMS, run the command:

        CREATE DATABASE books;

### 2. List Existing Databases

We can use the following command to generate a list of all available databases in the current RDBMS:

        SHOW DATABASES;

This will list not only the databases you (and your team) have created, but also RDBMS-managed databases that contain data related to the RDBMS setup, users, and other configurations.

As an example, if you are using MySQL, you may see a list of tables like:

        Database
        -------------------
        information_schema
        mysql
        performance_schema
        sakila
        sys
        books
        world

Except for the books database we just created, the databases shown here are system databases that include data MySQL needs to function correctly, as well as sample databases that are normally included in a MySQL installation. You may see different tables if you are using an existing SQL server or a different RDBMS.

> As a general rule, you should avoid using any database you did not create!

### 3. Use a Database

You can think of an RDBMS as an office building, where each office is a different database.

When you first walk into the building (or log into the RDBMS), you are in a virtual waiting room. This means that you have to tell the RDBMS which database you want to use, in the same way you would need to walk into the appropriate office to conduct your business.

To select a database, use the following command:

        USE books;

If you aren't sure what database you are using (or if you don't remember telling the RDBMS which database you want to use), you can run this command as many times as you wish. In fact, we generally recommend including a USE statement at the beginning of any SQL script to be certain that the script will run in the correct database.

If you decide later that you want to use a different database in the same RDBMS session, simply run another USE command with the name of the other database.

### 4. Delete an Existing Database

You can delete an existing database using the following command with the appropriate database name:

        DROP DATABASE books;

> This is Dangerous!  
> When you delete a database, you delete everything in that database, including all tables and data.

In a working, server-based RDBMS, only users with specific administrative permissions can delete databases, to prevent accidental catastrophes, and even then, permissions to delete databases are defined only when they are needed.

For this course, you are working with your own, local database, so you will be able to delete any database you create. You should, however, have scripts to rebuild a database you delete accidentally.
