## JSON

JSON is a plain-text format that uses a combination of key/value pairs. For example, the classic software development book Design Patterns might be encoded in JSON like this:

        {
            "title": "Design Patterns -- Elements of Reusable Object Oriented Software",
            "authors": ["Eric Gamma", "Richard Helm", "Ralph Johnson", "John Vlissides"],
            "publisher": "Addison-Wesley",
            "price": "$45.00"
        }

Here we have simple key/value pairs for title, publisher, and price. We also have a key/value pair for authors except that the value for the authors key is an array of values (the names of the book's authors).

One of the biggest advantages of JSON is the fact that is it easy to read, which also makes it easy to code. In the example above, it is very easy to understand what is being described and the details associated with the object. 

### 1. JSON in JavaScript

JSON is based on a subset of the JavaScript programming language. In JavaScript, JSON is a convenient and easy-to-use syntax for declaring JavaScript object literals.

        // JSON is everything after the =
        var lastSamurai = {
            "title": "The Last Samurai",
            "isbn": "978-0811225502",
            "rating": 9.5,
            "inPrint": true,
            "author": {
                "firstName": "Helen",
                "lastName": "DeWitt"
            }
        };

        // A JSON array containing four JSON objects
        var favoriteFoods = [
            { "name" : "Shepherd's Pie", "rating": 10 },
            { "name" : "Carbonara", "rating": 9.35 },
            { "name" : "Steel-cut Oats", "rating": 9.8 },
            { "name" : "Avocado Toast", "rating": 9.27 }
        ];

A JSON object literal is expressed as key/value pairs nested inside curly braces. JSON array literals are a series of values nested inside square braces. Values can be any valid JavaScript literal: strings, numbers, booleans, arrays, or JSON literals. JSON literals can be nested. 

### 2. Serialization

JSON is also used in serialization, independent of JavaScript. Serialization is the process of converting parts of a running program's in-memory state to a format that can be saved or shared. The reverse, deserialization, converts the formatted data back into in-memory state.

Continuing with the book example above, if the client requests a particular book from the web service, the web service will find the requested information, use serialization to put the data into JSON format, and send the JSON data to the client. The client will receive the JSON-formatted data, deserialize the data, and display the data to the user.

Similarly, if the user wants to add a new book to the service the client code will gather the new book's information from the user (via a form for example), put the information into JSON format, and then send it to the server.

This process is similar to reading data in from an external text file or writing data out to a file. However, the client and web service aren't reading and writing file data: they are exchanging data with another machine across the network and using JSON as a common format that both ends understand. 

### 3. JSON and Objects

Let's look at this serialization process more closely. A server-side application will typically be written in a standard programming language, like Java or C#. In the programming language, we represent data in data transfer objects. Data transfer objects (also referred to as model objects) consist of data members and getters and setters (for Java) or properties (for C#). The purpose of these objects is to ferry data between all the components of the application.

This works very well as long as all of the components in the application are written in Java or C# and are running in one program on one machine like the console applications we built in the first part of the course. Since everything is written in one language, all parts of the program can easily access these objects.

As we move into web services, however, we start to introduce other languages and technologies. For example, we often have client code written in JavaScript and server code written in either Java or C#. Although different parts of the service are written in different languages, we still must pass data between the components of the application. This is where JSON comes in. JSON is a format that both sides can understand and process.

We can represent the information for our book, Design Patterns, by setting the properties of a book object to the following:

* title = "Design Patterns – Elements of Reusable Object-Oriented Software"
* authors = {"Erich Gamma", "Richard Helm", "Ralph Johnson", "John Vlissides"}
* publisher = "Addison-Wesley"
* price = "$45.00"

Again, this is great for representing and sharing data between components that are written in the same language and running on the same machine, but it doesn't help us share data between Java or C# components running in one program on the server and JavaScript components running in another program in the browser. We need another mechanism.

We will use HTTP, JSON, and serialization code to share data between these components. The frameworks that we use to build web services have components built into them that take Java or C# objects and turn them into JSON strings like this and vice versa:

        {
            "title": "Design Patterns -- Elements of Reusable Object-Oriented Software",
            "authors": ["Eric Gamma", "Richard Helm", "Ralph Johnson", "John Vlissides"],
            "publisher": "Addison-Wesley",
            "price": "$45.00"
        }

Similarly, a JavaScript library like jQuery that we might use for client-side code has components that can do the same for JavaScript objects. These frameworks allow us to write code in whatever language makes sense (Java, C#, JavaScript, etc.) and then share data over HTTP using the JSON format.

Some things to keep in mind as you create these data transfer objects that will be serialized:

* Note that the keys in the JSON encoding must match the property names of the Java and C# objects.
* The Java framework component responsible for translating between Java and JSON relies on the getters and setters, not the actual fields of the class. So getTitle() will be used to get the value for the 'title' JSON key when going from Java to JSON. Similarly, setTitle(…) will be used to set the value of the JSON 'title' key on the Java object when going from JSON to Java.
* The C# framework component responsible for translating between C# and JSON will automatically change the case of the property names to lowercase for the JSON representation and then back to uppercase for the C# representation.

### 4. JSON Arrays

Let's look at how we represent an array of objects with JSON. This is pretty straightforward. For example, we might have the following two books and want to put them in an array:

        {
            "title": "Design Patterns -- Elements of Reusable Object-Oriented Software",
            "authors": ["Eric Gamma", "Richard Helm", "Ralph Johnson", "John Vlissides"],
            "publisher": "Addison-Wesley",
            "price": "$45.00"
        }

        {
            "title": "The Hitchhiker's Guide to the Galaxy",
            "authors": ["Douglas Adams"],
            "publisher": "Del Ray",
            "price": "$15.00"
        }

We simply separate the two by a comma and surround them with open ( [ ) and close ( ] ) square brackets like this:

        [
            {
                "title": "Design Patterns -- Elements of Reusable Object-Oriented Software",
                "authors": ["Eric Gamma", "Richard Helm", "Ralph Johnson", "John Vlissides"],
                "publisher": "Addison-Wesley",
                "price": "$45.00"
            },
        
            {
                "title": "The Hitchhiker's Guide to the Galaxy",
                "authors": ["Douglas Adams"],
                "publisher": "Del Ray",
                "price": "$15.00"
            }
        ]
