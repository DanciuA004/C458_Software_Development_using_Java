# Java Basics

## Java Components: JVM, JRE, and JDK 

Regardless of the code editor we may want to use, we must ensure that Java developer tools are installed on the computer if we want to write programs in Java.

Java itself includes three separate components:

- JVM (Java Virtual Machine): Software that works to convert compiled Java code to local machine language when we run a Java program 
- JRE (Java Runtime Environment): Tools required to run Java programs, including core classes and libraries 
- JDK (Java Development Kit): Tools required to develop Java applications, including a machine-independent compiler

### 1. JVM

One of the main design principles of Java is the idea of write once, run anywhere (WORA).

You may have experience with non-WORA applications. For example, you might have purchased a program written to run on an Apple computer and tried to install it on a Windows machine, or you may wonder why your favorite application in Apple's App Store is not available in Google Play for a friend's Android device. When developers write code that is device-specific (like using Swift to write an iPhone app), that code will run only on the targeted device. If they want the same program to run on another device, they have to rewrite the program in an appropriate code for the targeted device: twice the work for a single product.

With WORA, however, you can write the code once and then use other options to convert the code into a program that can run on virtually any device, as long as the device has software that can interpret it. For Java, this software is the JVM.

The JVM is essentially a virtual computer that includes its own instruction set and memory. It works as a layer between Java bytecode and the machine's operating system to interpret the bytecode into instructions that the computer's CPU can read and execute. Because of the JVM, Java is considered to be architect-neutral, meaning that the same application can run on any device that supports Java, unlike applications that are written for a specific architecture like Windows, macOS, or iOS.

During runtime, the JVM uses three components:

- Class loaders 
- A bytecode verifier 
- An interpreter

#### 1.1. Class Loaders

Class loaders gather all the necessary and supporting bytecode in a .class file needed to execute a Java program and during runtime, they dynamically serve the required bytecode to the JVM.

Because the class loaders identify and serve the required bytecode, the JVM does not need to know anything about the underlying file system to run the Java application.

#### 1.2. Byte Code Verifier

When code in a Java program is compiled, the compiler checks to make sure that the code satisfies all constraints of the Java language. If it does, the compiler converts the code into bytecode.

When you run a compiled Java program (in a .class file), the JRE delivers the bytecode to the JVM. However, because the code is compiled outside of the JVM, the JVM cannot assume that the bytecode was generated by the underlying computer or that it is properly structured and formatted. This is important when your application is importing bytecode from a non-trusted source or across a network from an unknown source.

To resolve this problem, the JVM includes a byte code verifier, a safety measure implemented in the Java language to improve security. When class loaders load bytecode into the JVM, the byte code verifier will check any code not associated with system classes to be certain that the code is safe to execute.

#### 1.3. Interpreter

The final step is to convert the verified bytecode into machine code that can be executed on the underlying hardware.

Because a computer cannot read bytecode directly, the JVM includes a just-in-time (JIT) compiler that converts the bytecode into machine code on the fly, one line at a time. The CPU then reads and executes the code for each instruction immediately. This is different from a traditional compiler where all the code must be compiled before the program runs; the result is that Java bytecode executes much more quickly than other code.

### 2. JRE

The JRE includes the minimum tools required to run a Java program. In other words, any user who wants to run a Java program must have a JRE installed on their device, and because Java is widely used for writing software, many systems already have a JRE installed.

The JRE includes the JVM as well as core classes and libraries required to run Java programs. It is machine-specific software, so a JRE written for Windows will not work on an Apple or Android device. This is also the source that the class loaders use to identify the bytecode required to run a Java program before the code is delivered to the interpreter in the JVM.

The JRE reads only bytecode, not the original Java code. This is why developers must compile and package Java programs before those programs can run on other computers. Java packages are often called JAR packages because they have the extension .jar (for Java Archive), and the JRE includes instructions needed to unpackage a JAR file and read its contents.

### 3. JDK

The JDK is not required to run a Java program that is already in bytecode, but we do need it if we want to write programs using Java. Like the JRE, the JDK is platform-specific, so you must install a JDK that is compatible with your device.

The JDK includes several tools for developing Java applications that are not included in the JRE, including:

- A compiler: used to convert Java code into bytecode 
- Debugger: helps identify errors in the code 
- Archiver: used to package a Java program into a distributable JAR file 
- Documentation Generator (Javadoc): Used to add common documentation comments to your code files

The JDK includes the JRE and the JVM, so once you have installed a JDK, you have everything you need both to write programs in Java and to run programs written on another machine. 

### 4. Choose an IDE

The term IDE stands for integrated development environment. While computer code itself is plain text (and it is possible to use a plain text editor like Windows Notepad, Mac TextEdit, or Linux Vim to write code), an IDE provides tools that streamline software development processes. These tools include:

- Syntax, highlighting, and error identification to help make the code easier to read and identify errors as you code 
- The ability to manage multiple files in the same window 
- Access to your computer's file management system 
- Built-in compilers 
- Customizable color themes so that you can decide how text appears in the window 
- Access to a command-line interface within the IDE itself 
- Support for multiple programming languages, especially languages that are often used together 
- Package managers that allow the developer to incorporate third-party packages into an application

All IDEs offer tools like those described above, but the way those tools are presented can differ from one IDE to the next, as well as from one version to the next of the same IDE. Newer versions also often offer tools that are not available in older versions, so we generally recommend that you try to use the most recent version of an IDE whenever possible. That said, if you are working in a team, you may find it useful that everyone on the team use the same IDE.

Because Java is an open-source programming language, there are a variety of IDEs available that support Java development processes. If you are already familiar with an IDE that supports Java and want to continue using what you have, you are welcome to do so.

If you do not have an IDE or if you want to try using a different IDE, we recommend using either NetBeans or IntelliJ. Both IDEs are available for Windows, macOS, and Linux. It is also possible to have two or more IDEs installed on your computer, but we recommend not having more than one version of the same IDE.
