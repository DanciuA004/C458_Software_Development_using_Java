## Enums

### 1. Magic Numbers

A magic number is a value that is hardcoded into your code but which does not have a clear meaning.

For example, suppose we had an order entry system. As each order is processed, it could have a status of Quoted, Purchased, Shipped, or Delivered. In languages that do not provide enums, a developer will often simply assign a numeric code to each status, so you could end up looking at code such as this:

        public void shipOrder(Order order) {
            if(order.getStatus() == 2) { // purchased
            // ship it
        
                // move to shipped status
                o.setStatus(3);
            }
        }

With the comments, the code is clearer, but without the comments, a developer unfamiliar with the order status codes would not know what 2 and 3 mean. Also, because software tends to change over time, what will happen when we add additional steps in the middle? For example, if we added a Gift Wrap stage in between Purchased and Shipped? In that case, the order of steps could end up being 1, 2, 5, 3, 4. The larger the workflow gets and the more insertions and deletions are made, the more unwieldy hardcoding numbers becomes.

This is where enums become useful.

### 2. Enums

Enums are a construct that allows us to define a group of related constants. In other words, we can define a controlled vocabulary for the constants we are interested in. For example, we can use an enum to define the order status options in the example above, define the days of the week, or even identify the different shifts at a factory.

You have already seen that constants are far better than hardcoded 'magic numbers' in your code. Enums take constants a step further in that they are all grouped together and are type-safe. It is also easier to see which enum values are valid and which are not.

Many sophisticated things can be done with enums; many of these are not available in other languages but these features are beyond the scope of this lesson, and your needs at this stage of your development career. We will concentrate on using enums as better constants.

#### 2.1. Creating Enums

Defining a Java enum is similar to defining a class or interface.

>In this example, we will define an enum for the basic math operators: plus, minus, multiply, and divide. We will then use this enum in a simple math program.

Creating an enum for use as a set of constants is straightforward. Simply list each item in the enum vocabulary in a comma-separated list in the body of the enum like this:

        public enum MathOperator {
            PLUS, MINUS, MULTIPLY, DIVIDE
        }

Because the enum items are constants, they should be named in all caps.

#### 2.2. Using Enums

One of the advantages of using enums over regular constants is that an enum is a proper type. This means that we can use a particular enum type in the formal parameter list of a method and in switch statements.

To illustrate this, we will create a class that performs simple math operations on two integers. This class has one method — calculate — that has three parameters:

1. The operation to perform 
2. Operand 1 
3. Operand 2

We then assign each of the enum values to a specific operation using a switch statement:

        public class IntMath {
        
            public int calculate(MathOperator operator, int operand1, int operand2) {
        
                switch(operator) {
                    case PLUS:
                        return operand1 + operand2;
                    case MINUS:
                        return operand1 - operand2;
                    case MULTIPLY:
                        return operand1 * operand2;
                    case DIVIDE:
                        return operand1 / operand2;
                    default:
                        throw new UnsupportedOperationException();
                }
            }
        }

Here are a couple of things to note about this code:

- The first formal parameter of this method is of type MathOperator, which is the enum type that we just created
- This guarantees that the only values allowed as operators are PLUS, MINUS, MULTIPLY, and DIVIDE. 
- When using an enum in a switch statement, the values in the case statements must be unqualified — in other words, PLUS vs MathOperator.PLUS 
- The return statements in each case negate the need for break statements 
- We have chosen to throw an UnsupportedOperationException if we don't recognize the operator.
